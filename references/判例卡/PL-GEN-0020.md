# 生成器往自动编号列表插条目，要整份复制锚点的 pPr

> 一条判例只讲一件事。写不成一句话的，拆成两条。

## 触发场景

`build_review.py` 用 `after(ps[i], [para('…')])` 往 §1.2.2 标准清单、§1.2.3 基础资料里插条目。
这些清单在源文档里是 Word **自动编号**列表（§1.2.2 `numId=8`、§1.2.3 `numId=9`），
序号不在文本里，靠 `numPr` 渲染。插入段落没有 `numPr`，渲染出来就没号。

## 做法

**错误做法**：交付稿出现「21.《建筑照明设计标准》…；《密闭空间作业职业危害防护规范》…；
22.《建设项目…》」——中间那条裸着。DOCX 里看着有文字，只有渲染成 PDF 才看得出没序号。

**次优做法**：只补 `numPr`。序号出来了，但清单段落的悬挂缩进来自 `pStyle`，
而 `para()` 生成的段落带 `ind firstLine=560`，于是编号与正文之间多出一段空白
（「17. 《工业企业总平面设计规范》」），软换行时还会把「4.」单独留在行尾。

**正确做法**：

```python
def para_li(anchor, s):
    """插入到"自动编号"列表里的段落：整份复制锚点的 pPr（pStyle＋numPr＋spacing＋jc）。"""
    p = para(s); app = anchor.find(W + 'pPr')
    if app is not None:
        old = p.find(W + 'pPr')
        if old is not None: p.remove(old)
        p.insert(0, deepcopy(app)); order_ppr(p.find(W + 'pPr'))
    return p
```

三处插入点统一改用它，并把「用得对不对」写进注释，避免下次有人改回 `para()`。

## 依据

- F3 `build_review.py`：锚点 `pPr` 为 `<w:pStyle w:val="14"/><w:numPr>…`，
  插入段落为 `<w:numPr>…<w:ind w:firstLine="560"/>`（无 pStyle）
- 交付稿 §1.2.2（现为 1～25 条连续）与 §1.2.3（1～7 条连续）

## 可复用规则

> 往自动编号列表里插条目时，整份复制锚点段落的 `pPr`，不要只补 numPr，
> 也不要保留自带的 firstLine 缩进；验收必须渲染后读 PDF。

## 反例或例外

插入正文段、表题、注时不适用（本就该用默认 pPr）。
同一列表只认 `numId`＋`ilvl`，从锚点复制即可，**不要新建 numId**——新建会从 1 重新编号。
