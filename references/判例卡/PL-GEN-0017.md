# 字号归一化要按表分级，一把梭会连累密表跨页

> 一条判例只讲一件事。写不成一句话的，拆成两条。

## 触发场景

改稿时表内字号很乱：同一张表里既有 8.5 pt、9.5 pt 又有 10.5 pt，还有继承样式没显式字号的。看上去最省事的修法是写一个循环，把"所有保留表"的字号统一设成一个规范值。这一步做下去不会报错，看不出任何异常——直到渲染出来发现一批密表跨了页。

## 做法

**错误做法**：`for size in tbl.xpath('.//w:sz|.//w:szCs'): size.set(W+'val','21')`，对所有保留表一律 21。它把用户送审件里**本来就统一的 9 pt 密表**也一起抬高。"统一"的动机是对的，动作是粗的。

**正确做法**：

1. **先量再改**。列出每张表的列数、行数，以及送审件里的字号分布，区分"常规表"和"密表"（列多、字密、原来就是小五）。
2. **分级归一化**：常规表归到规范规定的表内字号；密表按已确认范例保持小五。缩小密表字号要有依据——排版规范里的"密表适当缩小"条款，或用户确认。
3. **保留表与生成表共用同一字号常量**。生成器里 `table(..., size=19)` 和归一化里的 21 分属两套逻辑，必然产生 9.5/10.5 并存。
4. **改完重渲染逐页查**。判据：某页有表格但没有对应表题 = 延续页。归一化有没有新造出跨页表，只有这一步能发现。
5. **这是版式改动，要报账**。列清影响哪些表、哪些页，交用户确认。

## 依据

- F3 实测（马沟预评价报告，2026-10-02）：`build_review.py` 约第 341–346 行，注释写"保留表格常规五号，消除手改造成的 9.5/14 pt 混排"，动作为对所有保留表 `prop(rp,'sz',val=21)`。
- 送审件 `正式归档定稿版_最终交付版.docx` 里表4.1-1 是**整表 60 个 run 全为 `sz=18`**，并非混排；改后为 21。同批被抬高的还有表4.3-2、表5.1-1、表6.2-1、表8.2-1、表8.3-1、表10.1-1（均 18→21）。
- 同文档 `table()` 生成的新增表是 `sz=19`；故 32 张表并存 9.5 pt 与 10.5 pt 两种表内字号。
- 恢复表4.1-1 为 `sz=18` 后：整表 7 行一页（188→473.5 pt，横向页文本区下界 505.1 pt），总页数仍 60，仅物理第35/36页文本变化，其余 58 页逐页一致——说明**跨页是字号造成的，不是结构造成的**。

## 可复用规则

> 字号归一化必须按表分级（常规表按规范值、密表按范例小五），保留表与生成表共用同一常量，改完必须重渲染逐页查有没有新造出跨页表。

## 反例或例外

同一张表内部确实混排时（本项目表4.2-1 为 19+17 混排、表4.3-1 为继承+17+18 混排），归一化是对的。但**目标值不能拍脑袋取最大值**——应取该表多数 run 的字号或规范值。若某表原本就是整表统一的小五，那不叫混排，不要动它。
