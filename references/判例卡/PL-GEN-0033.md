# 编制要求只作参考项：依据层级只有三类，不写进规范

> 一条判例只讲一件事。写不成一句话的，拆成两条。

## 触发场景

给报告的某一章建或改「章节生成规范」，摊开依据来拆要求项（R 清单）。

手头通常有三类东西：**评价通则**（GBZ/T 277—2016）、**阶段技术标准**（预评价 GBZ/T 196—2025 等）、
**库内判定矩阵**。此外还有一类**编制要求**——ZW-JB-2014 系列，技术服务机构内部编的报告编制要求。

问题出在最后这一类：它常写得比标准细，容易让人以为「既然写得更细，就该照着做」，
于是把它列成平级的第四类依据，还按它设 R 项。

## 错误做法

第3章、第4章两份生成规范起初都写成「**四类基础提示词**」：通则／技术标准／**编制要求**／库内矩阵。
为编制要求单独设的要求项有：

| 要求项 | 编制要求里的说法 |
|---|---|
| 接触人员 | 「职业病危害因素及其存在的作业岗位、**接触人员**、接触时间、接触频度」 |
| 超标原因 | 「预期浓度（强度）范围超过限值时，应**分析超标原因**」 |
| 无防护措施时的范围 | 「在有条件的情况下，给出**无防护措施时**各岗位的**预期浓度（强度）范围**」 |
| 设施运行维护／用品使用 | 「职业病防护设施设置**及运行维护状况**」「个体防护用品的配备**与使用**情况」 |
| 取最新检测资料 | 「尽可能收集**最新**检测资料」 |
| 资料质量、种类和范围 | 「收集的检测资料的**质量、检测种类和范围应符合要求**」 |

再拿这些去审报告：报告没写「接触人员人数」「无防护措施时的范围」→ 判「**不符合**」。

**根子上的问题**：编制要求是内部文件，不属于国家职业卫生标准体系，
**不能作为「符合／不符合」的判定落点**。把它当依据，等于用一本内部文件给报告加强制项。

## 正确做法

### 一、依据层级只有三类

| 层级 | 是什么 | 决定什么 |
|---|---|---|
| **评价通则** | GBZ/T 277—2016 等 | **共性底限**：三分类、来源与发生（散）方式、影响人员、接触方式与时间频度、资料真实性 |
| **阶段技术标准** | 预评价 196／专篇 882／控评 197／现状 751 | 这一章**设不设、写什么、分几节** |
| **库内判定底表与项目规范** | 章节判定矩阵、《执行规范》 | 判定重点、体例、流程 |

**编制要求类文件（ZW-JB 系列）只作参考项，可执行可不执行**——
不列为依据、不设要求项、不写进规范，报告的编制依据清单里也不列。

### 二、原挂其名下的条目，回原文核一遍再定去留

**核原文是这一步的关键**，不是凭记忆判断「通则里有没有这条」。实测结果：

| 原要求项 | 回原文核查 | 处理 |
|---|---|---|
| 接触人员 | **277 §3.9／§3.10／§7.1.2 三处都写"影响人员"** | **改挂通则**，仍为要求项 |
| 注明检测数据来源 | 277 §7.1.1（资料真实性） | **改挂通则** |
| 以最近一份作类比基准 | 196 附录 C.3「收集近 1～3 年检测资料」 | **由 C.3 推得**，保留 |
| 超标原因 | 196 §10.2.5.3 只有"符合性分析"，**无"超标原因"** | **移除** |
| 无防护措施时的范围 | 196 §10.2.5.3 ④ 只覆盖"无检测数据"因素，**不含"无防护措施"情形** | **移除** |
| 资料质量、检测种类和范围 | 196 附录 C.3 无此句 | **移除** |
| 设施运行维护状况／用品使用情况 | 196 附录 C.2 f 只写"**配备情况**" | **移除**（改为按 C.2 f 写"配备情况"） |

**差一个词就决定留还是删**：277 §3.9、§7.1.2 写了「影响人员」，196 §10.2.5.1 只写「工种（岗位）」——
**通则有的、技术标准没写的，照样要写**（这条与 `PL-GEN-0029` 同源）。

### 三、移除后 R 编号顺移重排

第3、4章的 R 清单均由 **R1—R20 收为 R1—R18**，并同步改：

- 两份 `第*章_标题结构.md` 的落点表；
- `范例_第3章正文_马沟.md` 的对照表与第三节；
- `_work/out/qa/第4章_规范审视_20261004.md` 的逐条判定与汇总（不符合由 5 条减为 4 条）。

**编号跳号会被后人误当成漏项**，所以宁肯顺移重排一次。

## 依据

- 用户 2026-10-04：「**编制要求以后不采纳，改一下**」；「**编制要求仅作为参考项，可以执行也可以不执行，不用写进规范里**」
- 标准原文（N3）：277 §3.9／§3.10／§7.1.1／§7.1.2；196 §10.2.5.1—10.2.5.3、附录 C.2／C.3

## 可复用规则

> 规范里的依据层级只有三类：评价通则（共性底限）／阶段技术标准（设不设、写什么）／库内判定底表与项目规范。
> **编制要求类内部文件只作参考项，可执行可不执行**——不列为依据、不设要求项、不写进规范、
> 报告依据清单里也不列。旧规范里原挂其名下的条目，先回标准原文核：能支持的改挂过去，
> 挂不上的直接移除（不另设"可选加强项"占位）；移除后 R 编号顺移重排，并同步改标题结构、范例与审视报告。

## 反例或例外

- **参考项不等于不能用**：编制要求里有比标准更细、项目又做得到的做法，可以按它写——
  **但那是项目自己的选择，不是规范要求**，不能反过来用它判别处"不符合"。
- **报告正文里已列的那一条**（依据清单中标注"作为报告格式参考"）：要不要一并移除属**交付稿改动**，
  **先问用户再动**，不顺手删。
- **别把它当目录模板的来源**：报告目录以阶段技术标准的章节条款为准，编制要求附录的旧式章目只作理解参考。
- **编号重排要成体系**：只改生成规范、不改配套文件，会让同一项目里出现两套 R 号。
