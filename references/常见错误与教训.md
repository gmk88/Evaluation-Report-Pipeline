# 判例速查

从马沟项目记忆包 `04_判例卡片/` 的卡片头部（判例号、涉及章节、可复用规则）自动生成，后在晋钢冷轧薄板项目中补充（`PL-PRE-0037`～`0041`、`PL-GEN-0055`～`0056`），在晋钢200MW超临界煤气发电项目中补充（`PL-PRE-0042`、`0043`、`PL-GEN-0057`），在晋钢烧结烟气协同处置项目中补充（`PL-GEN-0058`、`0059`）；预评价 skill 只带下列几类。先按章节找相关判例，再打开 `判例卡/` 里的原卡看错误做法、正确做法和依据。卡片里的事实属于各自的来源项目（马沟加气站、晋钢冷轧薄板、晋钢200MW煤气发电等），只学规则，不搬事实。

> 注意档名：少数卡片（如 `PL-PRE-0034`）写的是第5章旧档名“合理／基本合理／不合理／不适用”；现行四档是 符合／基本符合／按补充措施完善后符合／无设置必要（第7章“无配备必要”，第8章只用前三档），以 `判定规则与口径.md` 为准。

| `PL-GEN-0016` | 版式结论必须注明渲染器；用户说"我看是好的"时先怀疑自己的渲染器 | 任意涉及分页/版式判断的章节 | 版式结论必须注明是哪个渲染器得出的；用户与我的渲染器不同时，用可复现的量化数据定位分歧机理，绝不用单一渲染器的结果宣布「无解」。 |
| `PL-GEN-0017` | 字号归一化要按表分级，一把梭会连累密表跨页 | 任意含表格章节 | 字号归一化必须按表分级（常规表按规范值、密表按范例小五），保留表与生成表共用同一常量，改完必须重渲染逐页查有没有新造出跨页表。 |
| `PL-GEN-0018` | 审文字稿：先查硬错，再查 AI 味 | 任何正文叙述章节的审稿 | 审稿顺序固定：硬错（标准名称版本 / 未发生程序 / 无证据事实 / 标题改动）→ 质感（生造机制名、流程编号化、定义式开头、四字并列、空话收尾、通用章节点名标准）。一句话判据：删掉该句后技术信息有无损失——无损失即废话；有损失但无证据即虚构。 |
| `PL-GEN-0019` | 给 DOCX 加横向页：先 dump 全部 sectPr，改方向要连列宽一起改，别为挪分段搬分节符 | 横向页 / 分节符（sectPr） | 动 DOCX 纸张方向前先 dump 全部 `sectPr` 摸清「节→内容」对应；关闭横向不要在分节符旁另插空段落（会生成只有页眉页脚的空白页），而应把表后首个既有分节符的 `pgSz` 换成纵向；改横向必须连列宽一起改——按各列最长单元格重分配、总宽取满横向文本区，并设 `fixed` ＋ 逐个 `tcW` 与网格对齐；移动分节符前先量「目标页剩余高度 vs 待并内容高度」（`sectPr` 结束的是它所在的节）；改完逐页比对横向页/空白页/页码，且基线已有空白页不计入新增问题。 |
| `PL-GEN-0020` | 生成器往自动编号列表插条目，要整份复制锚点的 pPr | 生成器插入段落；正文自动编号列表（1.2.1 法规、1.2.2 标准、1.2.3 资料等） | 用生成器往自动编号列表里插条目时，整份复制锚点段落的 `pPr`（pStyle＋numPr＋spacing＋jc），不要只补 numPr、也不要保留自带的 firstLine 缩进；验收靠渲染后读 PDF，看序号连续且缩进与相邻条目一致。 |
| `PL-GEN-0021` | 长程项目的项目记忆按「作业环节」分册，入口按任务类型＋报告章节双开 | 项目记忆结构 / 检索入口 | 长程项目的项目记忆用 1+n 结构：主文件只放指针与高频变动项（接续顺序、路由表、当前基线、悬置项、维护约定），内容按作业环节分装进 n 份分册；检索入口写成两维路由表（按任务类型 + 按报告章节），只加表、不加册——内容只能放一处，入口可以有多张表。判据：统计条目里「点名具体章节」的占比，跨章占比高（实测 71%）时按位置分册必然失败。主文件是目录不是正文：每格只留一句话＋指针，细则有唯一归属册，长枚举一律进分册；宿主报「注入被截断」即触发第二轮瘦身。 |
| `PL-GEN-0022` | 每章动笔前先列该节的官方要求、再定任务计划——不得先写内容再补依据 | 全部章节（动笔前的准备工序） | 每章动笔前先走五步：取导则要求（通则＋对应类型导则＋细则编制要求＋库内判定底表，四类收齐）→ 查判定矩阵定位本阶段行（认明示／关联／补足／专项四种标记）→ 认清判定依据是「阶段主文件＋章节通用标准＋专项标准＋项目事实证据」四层组合 → 把要求整理成该节的必答问题清单（不是条文摘抄）→ 产出任务计划表；计划未成不动笔。写完逐条回查必答问题是否都有落点。 |
| `PL-GEN-0023` | 报告内容优先表格化：检查表与一览表，表体随整体体例 | 全部章节（内容表达形式的选择与表体构造） | 报告内容优先表格化：逐项对照／核验／列举一律成表，首选检查表（要求项·现状·判定·建议，一列一义）与一览表（对象·参数·出处，出处可回查）；分析论证、判定理由、结论成段文字不塞单元格；表体必须沿用报告既有体例（表号表题、线型、列宽、字号分级），不为新表另起一套；一表一职责，参数级与汇总级分开。列头与列内容必须同类：程度／分级列只写分级结论（级别，或"未达分级起点，不作分级"，或"不作分级＋依据＋按××危害控制"），不写风险描述、不写"待定"；表内结论与正文对应段必须同口径。 |
| `PL-GEN-0024` | 删段落会连带删掉它承载的分节符——改字不删段，并给生成器加存活闸门 | 全文（分节符／横向页）——本轮实际落在第3章末 3.4 与第4章之间 | 删段落前先查该段是否承载 sectPr；承载者只能改文字、不能删段。生成器必须内置分节符存活与数量断言。页数异常先打整本横纵序列与基线比对，再谈内容。 |
| `PL-GEN-0025` | 表格每栏只回答自己列头的问题；删了栏内多余话，回头核表下小结 | 全部章节（所有检查表／对照表／判定表的单元格写作） | 表格每一栏只回答自己列头提出的问题，且篇幅要压到最低：列头怎么写，栏内就只写什么——列头是「差异」，栏内就只写差异、不留影响句；判定栏写判定；处理方式归对策措施章、不确定度归不确定度专表。差异对报告的影响集中写在表下小结一句，不逐格重复，也不在表下写「其影响见上表」这种指向空栏的话。正文表下小结声称某维度有差异时，回表核对表内该维度是否真有差异内容，没有就改小结而不是改判定。 |
| `PL-GEN-0026` | 表要收进同一页：先量三个数，再调列宽，最后才压正文 | 全部章节（凡表格跨页、需收进同一页的场合） | 要判断一张表能不能收进一页，先量再改：量出「表高」「页正文可用高」「当前占用」三个数，缺口大于前置正文可压缩量时，说明单删正文不可能达成，必须同时压缩表格本身。压缩表格的首选手段是重分配列宽（长文本栏加宽以减少文字行数，合计仍等于 8186 dxa），其次才是压缩与表内重复的前置正文；不许动字号、行距、拆表或删行。改完必须实测复核表格线坐标——判据是「表底是否在同一页」，不是「全文省了几页」（同轮还在往报告里加内容时，省下的页会被吃掉）。每次渲染后重定目录页码、横向页与各章起页基线。 |
| `PL-GEN-0027` | 关于资料的断言必须回附件核对：谁做的、几年、含不含 | 全部章节（凡陈述资料来源、出具机构、覆盖年度、资料类别构成的句子） | 报告里凡是关于资料本身的断言——谁出具的、覆盖几个年度、含不含某一类检查、是谁提供的——都属于可被附件直接证伪的事实，写之前必须把附件逐份打开核对（出具机构、编号、日期、覆盖范围、结论五项），核对不到结论时就写「资料已取得、结论未见」并保留缺口说明，绝不可反向写成「未含／没有」。同一事实在 §1（依据清单、项目背景）与 §3（类比调查）之间的表述必须一致。 |
| `PL-GEN-0028` | 导则要求必须回写成「章节生成规范」，留在 `_work/` 底稿里等于没落地 | 全部章节（任何一次「按导则补章」的动作） | 按导则条文补某一章时，取到的要求必须回写成三样东西才算落地：① 在 `知识库/评价各章节分阶段判定标准矩阵.md` 补上该章的专题节（追加在末尾，不插队重排）；② 在 `知识库/06_条款规则/章节生成规范/` 写一份六节齐全的章节生成规范，且自检清单的条目与要求项编号一一对应；③ 另配一份标题结构（`第<N>章_标题结构.md`），把 R1…Rn 逐项挂到三级标题上，写明每个标题挂哪张表。要求清单留在 `_work/` 底稿里等于没有落地——`_work/` 不被索引引用，下一个人不会读到它。只有 R 清单、没有标题落点，规范是悬在空中的：写的时候仍然不知道某一条该写在谁下面。判据：删掉全部对话、只留文件系统，接手的人能否查出这一章要写哪些项、每一项挂在哪个标题下、写到哪算够。 |
| `PL-GEN-0029` | 基础提示词要一次取齐：通则、技术标准、编制要求，缺一本整段漏项 | 全部章节（每一次「取导则要求」的动作） | 为某一章取依据时，四类来源一次取齐再动笔：评价通则（共性底限）／阶段技术标准（设不设、写什么）／编制要求（写到多细）／库内判定底表与项目规范。阶段技术标准没写某项，不表示该项没有要求——通则写共性底限、编制要求写细化，技术标准不重复写它们。拆完 R 清单要回头数：通则有几条、编制要求有几条落了进来；一条都没有就是漏了。依据节里必须把三本的分工写清，否则下一个人照样只取一本。 |
| `PL-GEN-0030` | 同一批事实多处陈述＋自造框架＝复杂度搬家；降层级＝删重复＋拆框架，不是删字数 | 任何带'事实→判断→对判断的自评'三层结构的章节（本案为预评价第3章 类比企业调查与分析） | 用户说某一章'复杂'时，先数两样东西再动手：① 同一事实在几处出现（正文/小结/表格，≥2 处就必须收敛到 1 处）；② 有没有自造的多要素框架（标准原文没有、为了'成体系'自己加的列或段）。降层级的动作是'删重复＋拆框架'，不是'拆长段＋改措辞'——后者只是把复杂搬家。删正文前逐个事实确认表里有承接，没有的先补进表再删。判据：读者从前往后读一遍，不需要回头重读任何一层。 |
