# AGENTS.md — 工作区文件与目录规则

本文件管**目录与文件怎么放**。项目事实、当前进度、技术口径见 `马沟预评价项目记忆与工作交接.md`。

## 当前协作分工（2026-10-04 用户明确）

- **Codex负责核心内容**：技术依据与适用性、项目事实核对、分析论证、正文与表格内容、结论及全文口径一致性。优先保证内容质量和输出速度。
- **WorkBuddy负责用户交办的简单任务**，包括排版、页码、目录回填、渲染及版面核验。
- Codex完成内容修改及必要的生成器内容同步后，交接修改位置、关联章节和待核事项；默认不运行整份报告构建、渲染、页码回填或逐页截图检查，除非用户另行明确要求。
- 双方共用工作区，修改前读取当前文件，保留对方已有改动；采用局部修改，不用旧快照覆盖现稿。
- 本分工优先于下文及历史规范中要求Codex每轮执行渲染、页码验证和全套整理的旧流程。内容任务保留必要的依据、数字、逻辑和跨章节一致性核验；记录简明，不将机械收尾扩大为新的任务。

## 阅读顺序（先读这两份，不要先扫目录）

1. **`工作区索引.md`** —— 自动生成。一眼看清：三份报告的交付状态与现行件哈希、根目录有什么、
   各目录干什么、`_work` 保留了哪些、关键脚本、以及交接文件的章节行号指针。
2. **本文件** —— 目录与文件规则。
3. 需要细节时，按索引里的**章节行号指针**挑读交接文件，不要整篇读（**566 行**，约 15—20k token；
   行数会随轮次增长，以 `工作区索引.md` 第六节的实测行数为准）。

> 背景：2026-10-02 清理前，本工作区因"每轮渲染新建一个带日期的目录 + 根目录当成输出目录"
> 累积到 7.7 GB、`_work/` 下 317 个目录、根目录 118 个文件，导致每次接续都要重新勘察。
> 索引 + 本文件 + `hygiene.py` 是为了不再发生同样的事。

## 一、根目录只放三类东西

1. **现行交付件**（每份报告最多 3 个文件：Word、PDF、必要的对照件）
2. **收件资料**（`原始资料/` `参考资料/` `附件/` `知识库/`，只增不改）
3. **独立记录**（项目交接、编制说明、核验记录、清理清单）

**禁止**在根目录产生：中间稿、试排稿、试渲染、备份、临时文件、脚本输出。

## 二、`_work/` 结构

| 路径 | 用途 |
|---|---|
| `_work/<现役目录>/` | 现役生成器、输入 JSON/MD、可编辑图源、证据快照 |
| `_work/out/` | **本轮**渲染与 QA 输出。目录名固定（`render1` `render2` `qa`），每轮开工前先清空 |
| `_work/tools/` | 治理脚本与本文件引用的工具 |
| `_work/.retention` | 保留清单：一行一个必须保留的目录名，`#` 起注释。脚本据此判定 |
| `_work/` 根层散文件 | 允许存在：脚本、图源、基线图、文本提取。禁止堆放试渲染产物 |

**核心规则：不要新建带日期的渲染目录。** 输出永远写 `_work/out/`，用固定短名。
需要和上一轮对比就复制成 `_work/out/prev/`，不要把旧轮次留在原处。

## 三、命名规则

- 交付件用**固定名**，不带状态词：`马沟加气站职业病危害预评价报告.docx`
- **禁用**「最终版 / 正式版 / 归档版 / 定稿版 / 最新版 / 完整版 / v2 / v3」表达状态——
  哪份是现行由**所在目录**决定，不由文件名决定。
- 确需留存的阶段性稿件，加日期后缀并放 `_work/out/`：`..._20261002.docx`
- 快照/备份统一 `backup_<日期>/` 前缀。

## 四、保留水位

- `_work/` 下**每份报告只保留最近一轮**构建与渲染，更早的进隔离区。
  未交付的报告（当前：控评、设计专篇）同样只留最近一轮，其交付件在根目录保留。
- 根目录同一份报告：现行件 + 至多 2 份溯源件，其余进隔离区。
- 隔离区命名 `_待删_<日期>/`，只作暂存，确认后**整体删除**，不得长期堆放。
  命令：`python3 _work/tools/hygiene.py archive`（把 `.retention` 之外的 `_work/` 子目录移入隔离区，移动不删除）
  ／`hygiene.py purge --yes`（确认后删除隔离区）。**不要自造 `_work/_attic` 之类的目录**——脚本不认，会被列为"待治理"。

## 五、每轮工作的收尾动作（必须做）

```bash
python3 _work/tools/hygiene.py scan       # 只读盘点 + 检查索引是否过期
python3 _work/tools/hygiene.py index      # 重生成 工作区索引.md（结构有变就跑）
python3 _work/tools/hygiene.py archive    # 把 .retention 之外的目录移入隔离区
python3 _work/tools/hygiene.py verify     # 跑渲染+目录页脚校验，确认没误伤
python3 _work/tools/hygiene.py purge --yes # 删除隔离区，真正释放空间
python3 _work/tools/memory_check.py       # 记忆体积检查（见下）
```

**memory_check.py 查什么**：宿主每次开工自动注入的只有 `MEMORY.md` ＋ 当天 `YYYY-MM-DD.md`，**两者共用一份预算**
（主索引超限被截尾＝最新内容丢失；日志超限整段不进上下文）。阈值：主索引与当天日志各 **10KB**，分册单册 6.5KB（软约定）。
**系统只在已经截断后才提示**——本脚本把检查前移到每轮收尾。判据出处：判例 `PL-GEN-0021` 补案。

**日志的记法（2026-10-04 定，用户要求"日志都记下来、将来复盘"）**：
- 当天 `YYYY-MM-DD.md` **只写简目**：每批一行标题＋关键结论＋待办。
- **过程详文一字不删**，写进 `.workbuddy/memory/_archive/<日期>_全文.md`（复盘用，永久保留，不占注入预算）；
  报告逐轮改动史另在 `_work/out/qa/`。三天的存量已于 2026-10-04 归档完毕。

`archive` 只移动不删除，可随时按 `_work/pre_eval_assets/清理记录/马沟工作区清理清单_*.csv` 还原
（逐文件「隔离区相对路径 + 文件名 + 字节」，可据此原样搬回）。

**加了新的现役目录或删了旧的，要同步改 `_work/.retention`**，然后跑 `index`：
索引里的"用途"说明就是从 `.retention` 注释里带出来的，改一处两处都更新。
`scan` 会比对指纹，索引过期会直接报出来。

### 收尾动作里还必须做的一件事：写判例卡

只要本轮出现下列任一情形，就在 `知识库/07_判例/判例卡片/` 写一张判例卡（格式见
`知识库/00_治理/模板_判例卡片.md`，机制见 `知识库/07_判例/README.md`）：

1. 用户提出批注或明确要求，而我原来的做法不对
2. 发现资料互相矛盾，或原始资料口径未明示
3. 确立了一个新的统一口径（数字、名称、章节结构、表述方式）
4. 发现标准条款与项目实际不适用，需要说明适用条件
5. 排版/图件被要求恢复某个基线样式
6. **发生了返工**——返工原因本身就是最有价值的判例

这条不是可选项。编制经验只存在于对话里，对话一结束就没了，下次同类问题会重新踩一遍。
蒸馏成技能的机制与阶段验收见 `知识库/编制技能路线图.md`。

**写完卡必须重跑索引**（索引从卡片自动生成，不手工编辑）：

```bash

```

新增卡片用编号 `PL-<类型码>-<四位序号>`，类型码 `PRE` 预评价 / `DES` 设计专篇 /

### 收尾动作里还必须做的一件事：更新项目记忆

`.workbuddy/memory/` 采用 **1+n 结构**：`MEMORY.md` 是系统唯一自动注入的主索引（只放接续顺序、
路由表、当前基线、悬置项）；`MEM/` 下 n 份分册按主题分装（**不自动加载，须按路由表显式 Read**）。
- **每轮重建后**更新 `MEMORY.md` §2 当前基线（哈希、页数、目录项数）。
- **新的口径/流程/踩坑**写进 `MEM/` 对应分册，**不要回流到 `MEMORY.md`**；分册超约 6000 字符就再分一册。
- 结构说明、分册清单与**两维路由表**（按任务类型 §1.1、按报告章节 §1.2）见 `MEMORY.md` 的 §1／§4；
  **动手改某章前先扫 §1.2 里该章那一行**。

## 六、清理前必须确认

- 任何删除/移动都在**用户批准**后进行；`purge` 必须带 `--yes`。
- 删除前先出清单（路径 + 体积），并说明保留了什么、为什么。
- **不按文件名判断新旧**，按内容哈希和实际修改时间判断。
- **`purge --yes` 之前先过一道闸门，挑出不可再生的来源资料**（2026-10-03 差点把收件原始包一起删掉后补入）：
  1. **找收件包**：`find 隔离区 -name "*.zip" -o -name "*.rar" -o -name "*.7z"`。凡「原始资料／参考资料／
     收件／交付包」一类命名的，即使解压目录还在，也先移回 `_work/pre_eval_assets/收件原始包/`。
     判据是**能不能自己重新生成**，不是「本地有没有第二个副本」——收件包本地往往只有一份。
  2. **找跨项目文件**：隔离区里出现非本项目名称的文件（别的站点、别的报告类型），到全盘确认正本
     在另一个项目目录里；确认不了就移出隔离区，别赌。
  3. **核未交付报告的最近构建**：控评、设计专篇等**尚未交付**的报告，其最近一轮构建与渲染必须在
     `_work/.retention` 清单内、且**在隔离区之外**。逐条打开 `.retention` 对照目录名，光看名字不算核过。
- 记得把「清理清单 CSV」移出根目录（属过程记录，不属根目录三类）：放 `_work/pre_eval_assets/清理记录/`。
